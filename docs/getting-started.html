Getting Started

Requirements

  • Python 3 and the Komodo reference interpreter (KomodoPy)
  • NASM — the Netwide Assembler (for x86 target)
  • GCC — GNU C compiler (for linking)

Setup

Clone the Komodo repository and set the path to the reference interpreter:

git clone https://github.com/lrperks/Komodo.git
cd Komodo
export KOMODO_MAIN="/path/to/KomodoPy/main.py"

If you haven't cloned KomodoPy yet:

git clone https://github.com/lrperks/KomodoPy.git ../KomodoPy
export KOMODO_MAIN="../KomodoPy/main.py"

Your First Program

Create a file hello.km:

import console

void main()
    print("Hello, Komodo!")

Compile and run it:

./build.sh hello.km

The script will:

  • Invoke the Komodo compiler on hello.km
  • Generate hello.km.asm (x86-64 assembly)
  • Assemble and link it with the C runtime
  • Run the result

Build Options

The build script accepts a target and output path:

./build.sh FILE [target] [output] [extra cc inputs...]

Targets

  • x86 (default) — native x86-64 assembly
  • stackvm — textual stack-VM bytecode (no runtime yet)

Examples

./build.sh examples/features_demo.km           # x86, run immediately
./build.sh examples/features_demo.km x86       # explicit x86
./build.sh examples/features_demo.km stackvm   # generate bytecode only

# Link external libraries
./build.sh demos/sdl_window.km x86 ./w -lSDL2

The compiler output (ASM or bytecode) is saved as <file>.km.asm or <file>.km.txt.

Running Tests

Run the built-in test suite:

./run-tests.sh              # all examples
./run-tests.sh oop_demo     # specific example

Each example is compiled to x86, run, and compared against its .expected file. The stack-VM target is also checked to ensure the target-independent lowering is correct.

Caching

The compiler caches parsed ASTs under ~/.km/cache for faster builds. The build script clears this cache each run, so edits to compiler modules always take effect. To manually clear:

rm -rf ~/.km/cache
