Compiler Architecture

Pipeline Overview

The compiler runs in a single pass:

  1. Lexing — tokenize source code
  2. Parsing — build an abstract syntax tree (AST)
  3. Type inference — resolve types and validate
  4. Code generation — lower to an intermediate operand stack
  5. Backend — generate target-specific code (x86 or stack-VM)

Modules Layout

Module Purpose
main.km Driver: resolves imports, concatenates sources, invokes compiler
lexer.kmm Tokenizer — produces a stream of tokens
parser.kmm Recursive-descent parser — builds AST
ast.kmm AST node definitions
codegen*.kmm Target-independent lowering (5 modules)
backend.kmm Backend interface (abstract base)
backend_x86.kmm System V AMD64 / NASM backend
backend_stackvm.kmm Stack-VM bytecode backend
km_compiler.kmm Entry points: compile, save, selectBackend

Lexer

Converts source text into a stream of tokens (identifiers, keywords, literals, operators, indentation changes).

  • Tracks line and column for error messages
  • Handles string/char escapes
  • Emits indent/dedent tokens for block structure

Parser

Recursive-descent parser that builds an AST from the token stream.

  • Handles expression precedence and associativity
  • Builds statement and declaration trees
  • Validates syntax structure

Type Inference & Checking

The compiler infers and validates types throughout the AST:

  • Resolves variable types from assignments
  • Checks function argument types
  • Validates struct and class field access
  • Handles generic monomorphization
  • Emits runtime type checks for ambiguous overloads

Code Generation (Target-Independent)

The codegen walk in codegen*.kmm never names a machine instruction. Instead, it:

  • Manages an operand stack
  • Calls the Backend interface for every operation
  • Handles frame layout and variable allocation
  • Processes statements and expressions uniformly

This allows new backends to be added without changing the lowering logic.

Backend Interface

Every backend implements the Backend trait with methods like:

fn emit_push(val: int)           // push value
fn emit_add()                   // pop two, push sum
fn emit_call(fn_name: string)   // call function
fn emit_return()                // return from function

Register allocation, calling conventions, and instruction selection are backend-specific.

x86-64 Backend

Implements System V AMD64 ABI and generates NASM-compatible assembly:

  • x86-64 registers and calling convention
  • Stack frame management
  • Function prologues/epilogues
  • Direct x86 instruction emission

Output can be assembled with nasm and linked with gcc.

Stack-VM Backend

Generates textual stack-VM bytecode for portability:

  • Simple stack-based instruction set
  • No runtime yet (under development)
  • Useful for validation and educational purposes

Object Representation

Objects in memory carry a one-word header with a type id:

  • Structs — flat C aggregates plus type tag (single inheritance appends fields)
  • Classes — reference types with vtable pointers, method inheritance, and virtual dispatch
  • x is Type — compile-time expanded type-id check

Adding a New Backend

To add a new compilation target:

  1. Create a new file backend_mytarget.kmm
  2. Implement MyTargetBackend : Backend with all required methods
  3. Register it in selectBackend in km_compiler.kmm
  4. The entire codegen pipeline works without modification
