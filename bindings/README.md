# Bindings

Komodo binding modules for popular C libraries. They are a convenience: any C
library works without one, through `import name` and
[`komodo`'s auto-binding](../docs/interop.md). Use a binding here when you want a
curated, tested module.

| Library | Folder | Needs (pkg-config) | Example |
| --- | --- | --- | --- |
| SQLite 3 | [sqlite3/](sqlite3/README.md) | `sqlite3` | open, exec, prepared statements |
| zlib | [zlib/](zlib/README.md) | `zlib` | `crc32`, `adler32` |
| PCRE2 (8-bit) | [pcre2/](pcre2/README.md) | `libpcre2-8` | compile and match a regex |

Each folder holds:

- `<lib>.kmm`: the binding module. Usually generated by `km-bind`, sometimes
  with a few hand-written helpers at the end (marked in the file).
- `<lib>_handles.c`: a C shim, only when a function returns a handle through an
  out-parameter or needs a NULL handle argument. Komodo cannot build a handle
  from an int or pass a NULL handle, so the shim does it in C.
- `example.km` with `example.expected`: a program and its exact output.
- `README.md`: what the binding covers and how it was made.

## Build and run the examples

```bash
scripts/build-bindings.sh            # all bindings; skips any whose library is not installed
scripts/build-bindings.sh zlib       # one binding
```

Each example starts with `// requires: <pkg-config name>`. CI installs the dev
packages, so every example runs there.

## Add a binding

1. Try the generator first. It needs only `gcc` and `awk`:

   ```bash
   mkdir bindings/<lib>
   tools/km-bind --auto <lib> -o bindings/<lib>/<lib>.kmm -v
   ```

   If the header is not found by name, pass it explicitly:
   `tools/km-bind /usr/include/<h>.h -p <pkg> -m <lib> -o ...`. Add `-D` for
   macros the header needs, such as `-D PCRE2_CODE_UNIT_WIDTH=8`.

2. Check the output for `// skipped:` lines. Function-like macros and `va_list`
   parameters are skipped. Read what the generated file says about return types
   and handles, and fix what matters in a short hand-written section at the end.

3. Write `example.km` with `// requires: <pkg>` on its first line. Keep it short
   and print results that do not depend on the system (no version strings).
   Generate `example.expected` by running it, and check the output by hand.

4. Add the library to the table above and write a short `README.md`.

5. Run `scripts/build-bindings.sh <lib>`. CI runs the whole script.

## Naming

- Folder, `.kmm` file and `module` name: the library's short name in lowercase
  (`sqlite3`, `zlib`, `pcre2`). The module name must not clash with a stdlib
  module (`math`, `string`, ...); use `c_<name>` if it does.
- Keep the C names. Komodo calls them as `lib::name(...)`.
- Only add a library that is in Ubuntu's `apt` archive, so CI can install it.
